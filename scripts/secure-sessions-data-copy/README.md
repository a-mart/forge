# Secure Sessions real-data E2E harness

This directory prepares and launches a private, isolated copy of Forge data for Secure Sessions
end-to-end validation. It never prints credential values and refuses to copy while the source
`runtime.lock` exists.

The preparation is deliberately fail-closed:

- source and target must be absolute, non-overlapping, non-symlink roots; regular-file symlinks
  inside the source are materialized so the destination cannot alias the source or another host path,
  while directory and special-file symlinks are refused;
- ordinary files are copied with archive metadata; extended attributes are
  deliberately omitted because macOS OpenRsync synthesizes transient AppleDouble
  entries that cannot be copied coherently from this live APFS tree;
- SQLite databases are copied through the read-only SQLite backup API and checked with
  `PRAGMA quick_check`;
- non-SQLite source metadata must remain unchanged for the full copy;
- schedules, goals, terminals, mobile state, Collaboration state, observability, telemetry,
  remote-build policy, extension/package execution, and project-resource trust are preserved under
  `.secure-sessions-quarantine/` but removed from active paths;
- provider authentication remains active and is restricted to owner-only permissions;
- an existing valid target is an idempotent no-op, while an unknown existing target is refused.

## Synthetic validation

Run before using real data:

```bash
node --test scripts/secure-sessions-data-copy/__tests__/*.test.mjs
```

## Prepare the real copy

First use Forge **Stop All**, wait for all agents to settle, and quit the production Electron app
cleanly. Verify `/Users/adam/.forge/runtime.lock` is gone. Then run:

```bash
node scripts/secure-sessions-data-copy/prepare-isolated-data.mjs
```

Defaults:

- source: `/Users/adam/.forge`
- target: `/Users/adam/.forge-e2e-secure-sessions-20260723`
- backend: `47687`
- UI: `47688`
- Electron state: `/Users/adam/Library/Application Support/@forge/electron-secure-sessions`

Do not copy the production repository `.env`. Provider credentials are retained from the copied
Forge auth files; direct Codex can still use host-global login state.

## Validate and launch

The launch requires the development-only Electron overrides
`FORGE_ELECTRON_DEV_SERVER_URL` and `FORGE_ELECTRON_USER_DATA_DIR`.
Each launch first moves any schedules or other automation state regenerated by
an earlier isolated run into a uniquely named quarantine directory, then
revalidates the complete isolation boundary. This makes repeated E2E passes
safe without discarding the prior copied state.

```bash
scripts/secure-sessions-data-copy/launch-electron.sh --check-only
scripts/secure-sessions-data-copy/launch-electron.sh
```

The launcher binds both services to loopback, disables telemetry/Cortex/terminal restore/skill
sharing/Remote Projects/versioning/debug logging, checks the copied data again, refuses occupied
ports, and runs the UI and Electron in one foreground lifecycle.
