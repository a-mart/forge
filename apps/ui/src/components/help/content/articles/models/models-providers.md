Forge supports five AI providers. Each has a different set of models with different tradeoffs.

## OpenAI / Codex

OpenAI offers GPT models through the Codex runtime. OpenAI/Codex can use local OAuth/API-key credentials or Forge Auth broker mode in v1. Broker-backed access is normally bootstrapped by pasting a one-time admin setup link in Settings > Authentication; Forge redeems it server-to-server and stores only the broker runtime token in secrets. While broker mode is active, local OpenAI credentials are visible in Settings for reference but read-only. Separately, Builder web can send a plain leading @Codex or [@Codex] text message to a direct Codex app-server sidecar thread. Selector forms like @Codex -<plugin>, @Codex:<plugin>, and [@Codex:<plugin>] scope the turn to a plugin and delegate it through the visible Codex Plugin specialist worker. The plugin-scoped path uses server-owned scoped exact plugin tools, stays read-only/safety-gated, and returns bounded redacted previews and metadata. Full connector exports are written to session artifacts instead of returned through normal worker tool output. The direct sidecar path requires the Codex CLI app-server, is text-only, and is not available in Collaboration.
- **GPT-6 Astra** — OpenAI's most capable Codex model for complex work across code, apps, and research. Forge exposes it as the separate `pi-6` preset with low, medium, high, xhigh (shown as Extra High), and max reasoning; high is the Astra reasoning default. It does not replace the Forge `pi-5.5` global default. Astra has a 1.05M-token context window and 128k maximum output. Availability follows the OpenAI account's rollout entitlement, so an unavailable account receives the provider error when it tries to run Astra.
- **GPT-5.6 Sol** — The GPT-5.6 flagship Codex model. Supports low, medium, high, xhigh (shown as Extra High), max, and ultra reasoning.
- **GPT-5.6 Terra** — A GPT-5.6 variant selectable under the same family. Supports low, medium, high, xhigh (shown as Extra High), max, and ultra reasoning.
- **GPT-5.6 Luna** — A GPT-5.6 variant selectable under the same family. Supports low, medium, high, xhigh (shown as Extra High), and max reasoning.
- **GPT-5.5** — The standard full Codex coding model. Strong at implementation tasks, refactors, debugging, planning, architecture, and multi-step reasoning. Supports the legacy OpenAI Codex reasoning scale.
- **GPT-5.4** — Prior full OpenAI coding model. Good for complex planning, architecture, and multi-step reasoning when 5.5 is unavailable or intentionally avoided.
- **GPT-5.4 Mini** — A smaller, faster variant of 5.4. Good for lightweight tasks like reading files, quick edits, and exploration. Much cheaper than the full model.

## Anthropic

Anthropic offers the Claude model family through Forge's native Anthropic runtime path.

- **Claude Fable 5.1** — Anthropic's premium option for demanding reasoning and long-horizon agentic work. The visible `pi-fable` preset selects `claude-fable-5-1` at high reasoning by default for managers and specialist workers; Claude Fable 5 remains an explicit variant. Fable 5.1 has a 1M-token context window, supports up to 128k output tokens per request, and is priced at $10 per million input tokens and $50 per million output tokens, with lower $0.25 per million cache reads. Adaptive thinking cannot be disabled, so Forge offers low, medium, high, xhigh, and max but not none; at lower effort, the model can still skip thinking for simpler requests. Automatic and disabled tool choice work, but Anthropic rejects forced `tool_choice` values (`any` or a named tool). Anthropic's safety classifiers can decline some requests, including benign false positives; in Forge's Pi runtime, a refusal surfaces as a runtime error rather than an automatic model reroute. Anthropic designates Fable 5.1 a Covered Model requiring 30-day provider retention, so it is unavailable under zero data retention (ZDR) unless Anthropic expressly authorizes it.
- **Claude Opus 5** — The Opus family default. The visible `pi-opus` preset selects `claude-opus-5` at high reasoning by default for managers and specialist workers. It has a 1M-token context window by default, supports up to 128k output tokens per request, and is priced at $5 per million input tokens and $25 per million output tokens. Thinking is on by default; Forge `none` disables it. Unlike Fable, Opus 5 supports none, low, medium, high, xhigh, and max. Do not combine disabled thinking with xhigh or max (the provider returns 400). Anthropic's safety classifiers can decline some requests, including benign false positives; in Forge's Pi runtime, a refusal surfaces as a runtime error rather than an automatic model reroute. Unlike Fable 5, Opus 5 has no special 30-day Covered Model retention requirement.
- **Claude Opus 4.8** — An older Opus variant that remains selectable. It is particularly strong at frontend work, UI polish, writing, and nuanced code review. Reasoning levels are limited to low, medium, and high (no none, xhigh, or max).
- **Claude Sonnet 5** — The default Sonnet model, with a 1M-token context window. Faster than Opus, still capable, and good for documentation, lighter code tasks, and cases where Opus is overkill. The `pi-sonnet` preset selects Sonnet 5.

## OpenRouter

OpenRouter entries are user-added overlays, not checked-in Forge catalog families or presets. Forge records `supportsTools` only when live OpenRouter metadata confirms tool-call support; client-supplied capability claims are not trusted. When OpenRouter settings load, Forge automatically reconciles older rows against current live metadata. A verified row still starts with its per-model **Manager agents** setting off. Enable it explicitly with `managerEnabled: true` under the exact `openrouter:<model-id>` override before selecting it for a manager.

Manager create, change, and per-session override flows require the exact OpenRouter provider and model ID. There is no family or guessed-ID fallback. A configured OpenRouter API key is also required (Settings > Authentication or `OPENROUTER_API_KEY`). Rows that cannot be matched or refreshed remain unverified until a later settings reload succeeds, and rows with `supportsTools: false` remain non-manager entries. Removing a row clears its manager override, and re-adding it starts with manager access off again.

This manager policy is separate from compaction. OpenRouter is not a supported Forge compaction provider, so an OpenRouter model does not appear in the compaction model selector even when it is manager-enabled. Retired OpenRouter IDs are hidden and rejected rather than migrated across providers; choose a new exact ID.

## Cursor SDK

Cursor SDK uses Forge's Cursor SDK auth entry and exposes Composer 2.5 plus Cursor Grok 4.5 (`grok-4.5` and `grok-4.5-fast`). It is native to the Cursor runtime, and background auth/transport failures stay contained in the worker runtime and show up as worker failures, not app crashes. Codex selector mentions are separate from model selection and do not make Codex a manager model; they scope the turn to a plugin and delegate it through the visible Codex Plugin specialist worker instead.

## xAI / Grok

xAI provides the native Grok model family. Settings manages one direct, non-pooled xAI credential slot: save an API key or use OAuth, with either choice replacing the other. Browser OAuth offers **Open authorization URL** and **Copy URL**, plus full callback-URL paste when needed. Device login supports remote or headless backends. Forge refreshes stored xAI OAuth tokens; retry or reauthorize if authentication cannot recover.

- **Grok 4.6 (`grok-4.6`)** — The native xAI default with a 500k context window, text and image input, tools, structured output, and low, medium, high, or xhigh reasoning (default high). It is eligible for manager creation, model changes, exact per-session overrides, specialists, and worker spawns when xAI auth is configured.
- **Grok 4.5 (`grok-4.5`)** — The prior native model retained as an explicit variant with the same Forge reasoning scale. OAuth starts checked-in Grok models with a low/medium/high fallback; authenticated discovery can provide the account's available reasoning choices.
- **Grok Build (`grok-build`)** — An OAuth-only worker/specialist model that appears only when the active xAI account reports the entitlement.
- **Grok Composer 2.5 Fast (`grok-composer-2.5-fast`)** — Another account-specific OAuth-only worker/specialist model. Despite the similar name, this native xAI model is not Cursor SDK's `composer-2.5`.

OAuth model discovery is dynamic and account-specific, so the two entitlement models and their reasoning choices may differ by account or disappear after a refresh. Authenticated discovery accepts only the approved `grok-4.6`, `grok-4.5`, `grok-build`, and `grok-composer-2.5-fast` IDs; the checked-in Grok 4.6 and Grok 4.5 models remain available. Switching to API-key auth hides the two entitlement models and rejects stale entitlement selections before a provider request. Losing entitlement or failing discovery removes them from refreshed catalog, projection, and selector results.

You need provider credentials for each provider configured in Settings > Authentication before its models appear in eligible selectors. For OpenAI/Codex, those credentials can come from local auth or Forge Auth broker mode. OpenRouter requires its own configured API key in addition to live tool verification and the per-model manager opt-in; adding an OpenRouter row alone is not enough. Cursor SDK uses Forge's Cursor SDK auth entry, and models can be disabled in Settings > Models if you do not want to see them. Native xAI `grok-4.6` and `grok-4.5` are eligible for normal manager create, change, and exact per-session override selectors, plus specialist and spawn usage, when xAI auth is configured and the model is visible. The OAuth-only `grok-build` and `grok-composer-2.5-fast` remain entitlement-gated worker/specialist choices excluded from normal manager selectors. Manager-facing availability for eligible checked-in providers is also controlled in Settings > Models. Codex selector mentions are plugin-scoped turns that delegate to the visible Codex Plugin specialist, not the manager model selector list. Compaction settings apply only to supported Pi-backed manager compaction runtimes, currently OpenAI/Codex and Anthropic; OpenRouter manager eligibility is separate and does not add OpenRouter to compaction.

Former Claude SDK sessions use native Anthropic after load when the saved model is known. Configure Anthropic in Forge because Claude Code login credentials do not transfer. Continued sessions use native Anthropic reasoning and compaction behavior rather than the former SDK semantics. Unknown saved SDK models and user-authored SDK references remain unavailable until you choose a native Anthropic model; Forge leaves canonical history and external Claude Code data untouched. Rollback requires reinstalling the prior binary; Forge does not rewrite historical or external Claude Code data.
